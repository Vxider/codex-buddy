uConsole 8 x WS2812 灯柱方案

面向 uConsole + CM5 + codex-buddy 的侧板长条状态灯方案。目标是在一块小板上集成 8 颗 WS2812，对主板只暴露 5V / GND / DIN 三根线，其中控制线只有一根。

方案：8 x WS2812 板载灯条 控制：单线数据 + 5V 供电 推荐主控脚：GPIO18 版本：V1 可装机版

1. 目标与边界

这版方案不再使用单颗模拟 RGB 灯，而是改成一块线性排布的小型数字灯板：

  • 1 x 8-LED WS2812 小板
  • 1 x 改造侧板
  • 1 x 背部固定座 / 遮光座
  • 1 x 电平转换小板或转接区域

默认假设：

  • 机型：uConsole
  • 核心板：CM5
  • 安装位置：扩展舱侧板
  • 状态来源：codex-buddy 守护进程
  • 灯效定位：状态反馈优先，不追求高亮玩具灯条效果

2. 先说结论

推荐你采用一块 8 颗直线排布的 WS2812 小板，通过 5V + GND + DIN 三线接到 uConsole 主板 J3。控制脚首选 GPIO18 (Pin 12)，数据线上串 330R，并增加 3.3V 到 5V 电平转换，灯板入口处并联 470uF - 1000uF 电容。

这版方案成立的前提是：你现在要做的是“真正的 8 像素灯柱”，而不是单颗状态点。

为什么它比单颗 RGB 更值

  • 一个长条窗口就能做连续的流动、呼吸、扫描效果。
  • 对主板只占 1 根数据脚，线束更干净。
  • 后续想从 8 灯扩成 12 灯或双段灯柱，软件模型保持一致。

为什么它比单颗 RGB 更复杂

  • 需要稳定的 5V 供电和去耦。
  • 需要考虑 3.3V 数据脚到 5V 灯珠的电平兼容。
  • Linux 侧驱动不能简单 bit-bang，要走专门库。

3. 系统结构

推荐结构如下：

uConsole 主板 J3
  -> 5V
  -> GND
  -> GPIO18 (DIN)
  -> 电平转换 + 串阻
  -> 8 x WS2812 小板
  -> 侧板长条窗口 / 灯柱

4. 引脚与接线建议

4.1 主板侧推荐接法

用途 J3 物理脚 信号 说明
电源 Pin 2 或 Pin 4 5V 给灯板供电。推荐只接其中一个脚即可。
地 Pin 6 或 Pin 39 GND 必须和数据发送端共地。
数据 Pin 12 GPIO18 作为 DIN 首选输出脚。

4.2 为什么首选 GPIO18

  • 在树莓派生态里，GPIO18 是地址灯常见的首选脚位。
  • 后续如果使用基于 DMA 的驱动方案，围绕这根脚的资料最多。
  • 相比继续占用 17 / 27 / 22 三路脚位，它更匹配单线灯协议。

4.3 灯板侧建议接口

焊盘 方向 必选 说明
5V 输入 是 主供电输入。
GND 输入 是 与主板共地。
DIN 输入 是 接电平转换后的数据线。
DOUT 输出 否 建议预留，为后续串接第二块灯板准备。

5. 电气设计建议

5.1 正式装机建议

  • 数据线串联 330R 电阻。
  • 使用 74AHCT1G125、74AHCT1G17 或 74HCT14 做电平转换。
  • 灯板电源入口并联 470uF - 1000uF 电解电容。
  • 每颗 LED 附近布置 0.1uF 去耦电容。
不建议把 CM5 3.3V GPIO 直接长期裸连到 5V WS2812 DIN 作为正式版接法。短线、单颗、实验环境下有机会工作，但不是稳定量产方案。

5.2 功耗估算

状态 估算电流 说明
8 颗熄灭 接近 0 只有极小待机损耗。
8 颗低亮彩色 60mA - 150mA 适合作为正常状态灯工作区间。
8 颗全白高亮 理论最高约 480mA 不建议作为默认模式，会刺眼且增加发热与压降。

V1 软件建议默认亮度限制在 32/255 到 64/255 之间。

6. 板型与结构建议

6.1 板型

  • 优先用 8 连直线排布，不要做 2 x 4 矩阵。
  • 如果空间紧，优先考虑 WS2812B-2020 或 SK6812MINI-E 一类更小封装。
  • 如果你买现成板，先确认板长是否适合侧板开窗，不要先买再倒推窗口尺寸。

6.2 侧板窗口建议

外观路线 窗口尺寸建议 适用情况
短灯柱验证版 3mm x 18mm 到 4mm x 22mm 快速验证可视效果。
正式长条窗口版 4mm x 22mm 到 5mm x 28mm 更像真正的设备状态灯柱。

建议在灯板和外部出光面之间保留 1mm - 2mm 混光距离，并配套黑色遮光座。

6.3 装配关系

侧板外表面
  -> 长条窗口
  -> 灯柱 / 导光件（可选）
  -> 混光空腔
  -> 8 x WS2812 小板
  -> 背部固定座 / 遮光座
  -> 三芯线束（5V / GND / DIN）

7. 软件驱动建议

这版硬件面向 Linux 主机直接控灯，不走额外 MCU 中转。

  • 不要自己用普通 GPIO 翻转时序。
  • 应优先选用树莓派生态里成熟的地址灯驱动库。
  • 软件层应把灯珠抽象成长度固定为 8 的像素条，而不是单颗 RGB。
对 codex-buddy 来说，建议把状态灯适配层做成一个独立输出模块： 输入是统一状态，输出是 8 个像素的颜色帧和动画策略。

8. 状态映射建议

idle / online
中间 4 颗绿色常亮，两端熄灭。
running
蓝色低亮流动，从下往上滚动。
attention
黄色双向扫描，节奏要慢，避免像告警灯。
error
整条红色脉冲，间隔闪烁。

补充建议：

  • 会话完成：青色快速扫过一次，再回到基础状态。
  • running_bash：蓝白交替短脉冲，但亮度应低于错误状态。
  • offline：全灭。

10. 风险与规避

风险 1：数据不稳

  • 确保共地。
  • 数据线尽量短。
  • 保留电平转换，不要省这一级。

风险 2：亮度过高

  • 软件默认限制全局亮度。
  • 不要把“全白 255”当常规工作状态。

风险 3：长条窗口串色不均

  • 加入黑色遮光座和小混光腔。
  • 不要让灯板紧贴最外层出光面。

风险 4：侧板空间不足

  • 先测量背面净空，再决定现成板还是自绘板。
  • 必要时改用更小封装灯珠。

11. V1 实施顺序

  1. 先确认侧板背后净空和可开窗口长度。
  2. 选定现成 8 灯板，或者确定自绘板尺寸。
  3. 先在桌面环境完成 GPIO18 + 电平转换 + 8 灯板 点亮验证。
  4. 再做侧板窗口和遮光座，不要反过来。
  5. 最后再把软件状态映射接进 codex-buddy。

12. 最终推荐口径

如果你现在准备把侧板状态灯升级成真正的“灯柱”，那就把方案收敛到： 一块 8 颗直线排布的 WS2812 小板，J3 提供 5V / GND / GPIO18，经过电平转换后单线驱动，软件限制亮度，窗口后面配遮光座。

这版方案比单颗 RGB 复杂，但复杂度是有回报的，因为你真正用到了数字灯的多像素能力。
